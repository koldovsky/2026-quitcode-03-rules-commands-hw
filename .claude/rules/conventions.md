# Conventions — як пишемо код у lead-sync

## Контекст

Кожен пункт закриває конкретний клас дефектів, який уже коштував інциденту:
секрети в журналі, падіння на неочікуваній відповіді, тихе пошкодження стану.
Пояснення «чому» — `materials/architecture-brief.md`.

## Правило

- **Помилки — це значення.** Функція, що може не вдатися, повертає `Result<T>`.
  `send()` інтеграції не кидає винятків назовні — лише `Result<void>`.
  Успіх — це `{ ok: true, value: undefined }`, а не `throw`/`null`.
- **HTTP** — тільки `postJson()` з `core/http.js`. Не `fetch`, не axios / got / ky.
- **Змінні середовища** — тільки `readEnv("NAME")`. Не `process.env` поза
  `core/config.ts`. Значення секретів не логуй, не вшивай у код і не клади в
  повідомлення про помилку.
- **Будь-який зовнішній JSON** — відповідь API, вебхук, файл стану — тільки
  `parseJson(text, guard, "label")`. Не `JSON.parse`. Невалідний JSON або
  неочікувана форма → `{ ok: false, error }` плюс `log.error`.
  **Ніколи** не підставляй мовчки значення за замовчуванням: так пошкоджені дані
  стають непомітними.
- **Журнал** — тільки `log.info` / `log.warn` / `log.error`. Не `console.*`:
  `log` маскує токени через `redact()`, `console` друкує їх як є.
- **Типи** — без `any` (ні `: any`, ні `as any`, ні `<any>`). Для невідомого —
  `unknown` плюс guard із `core/parse.js`.
- **Залежності** — не додавай пакетів і не редагуй `dependencies`. У коді
  застосунку імпортуй лише відносні шляхи та `node:*`; у тестах — ще `vitest`.
  Потрібна бібліотека — спитай людину, не `npm install`.
- **Мінімізація даних.** У сповіщення (Slack, месенджери) йдуть лише `name`,
  `source`, `budgetUsd`. `email` і `phone` — тільки в системи обліку (таблиця, CRM).
- **Імена** — файли kebab-case, експорт camelCase, `name` інтеграції = ім'я файлу.
- **Тести** — `*.test.ts` поруч із модулем, мережі немає:
  `vi.stubGlobal("fetch", …)` і `vi.stubEnv(…)`. Для інтеграції мінімум три випадки:
  успіх (перевір URL і тіло запиту), відсутня змінна середовища, помилка від
  зовнішньої системи.
- ⚠️ `check:rules` **не сканує `*.test.ts`** — перевірено: `any`, `fetch` і
  `process.env`, дописані у `slack-notify.test.ts`, лишили TOTAL 8. Відсутність
  порушень у звіті не означає, що тест чистий: ці конвенції діють і в тестах,
  і тут їх контролює лише рев'ю.

## Як перевірити

- `cd app && npm test && npm run typecheck && npm run check:rules`:
  тести зелені, typecheck без помилок, і у звіті `check:rules` немає жодного
  рядка з файлом, який ти змінив.
- Змінив наявний файл — порівняй TOTAL до і після: воно має **зменшитись або
  лишитись тим самим**, ніколи не зрости.
