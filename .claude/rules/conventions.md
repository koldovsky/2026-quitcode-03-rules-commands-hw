# Conventions

## Контекст

Конвенції з `materials/architecture-brief.md`: вони тримають HTTP, env, JSON і
логи в одному контрольованому місці, щоб один дірявий модуль (токен у логах,
неперевірений JSON, fetch без таймауту) не ставав інцидентом для всього
воркера. `app/scripts/check-rules.mjs` перевіряє їх автоматично.

## Правило

- Помилки — значення: функції, що можуть не вдатися, повертають `Result<T>`;
  інтеграція ніколи не кидає виняток назовні — `send()` завжди повертає
  `Result<void>`.
- Не використовуй `fetch()` напряму — використовуй `postJson()` з
  `app/src/core/http.ts` (таймаут, повтори на 5xx/429, маскування URL у журналі).
- Не читай `process.env` напряму — використовуй `readEnv(name)` з
  `app/src/core/config.ts`.
- Не використовуй `JSON.parse()` напряму для зовнішніх даних (відповіді API,
  вебхуки, файл стану) — використовуй `parseJson(text, guard)` з
  `app/src/core/parse.ts`; невалідна форма — це `Result` з `ok: false`, а не
  тихий дефолт.
- Не використовуй `console.*` — використовуй `log` з `app/src/core/log.ts`
  (маскує секрети; `console.*` друкує їх як є).
- Не використовуй `any` (ні `: any`, ні `as any`, ні `<any>`) — використовуй
  `unknown` разом із guard-функцією.
- Не додавай нових runtime-залежностей (`npm install` пакета, новий рядок у
  `dependencies`) — застосунок має лишатись на нулі; потрібна бібліотека —
  спершу питання в PR.
- У сповіщення (Slack, месенджери) не передавай email і телефон ліда — лише
  ім'я, джерело, бюджет; повні дані — тільки в системи обліку (таблиця, CRM).
- Файли — kebab-case; поле `name` інтеграції збігається з іменем файлу.

## Як перевірити

- `cd app && npm run check:rules` — рядки `http-via-core`, `env-via-config`,
  `json-via-parse`, `log-via-logger`, `no-any`, `no-new-deps` не зростають для
  зміненого файлу відносно значення до зміни (базова лінія — 8 порушень у
  спадковому коді, зафіксована в README).
- `cd app && npm test && npm run typecheck` — обидва зелені.
