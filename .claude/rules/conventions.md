# Конвенції коду і тестів

## Контекст

Воркер працює без нагляду вночі, тому помилки мають бути видимими значеннями, а не
винятками, і жодні дані клієнта не повинні витікати в журнал чи месенджер
(`materials/architecture-brief.md`, розділ «Конвенції коду»).

## Правило

- Помилки — значення: функція, що може не вдатися, повертає `Result<T>`.
  `send()` інтеграції не кидає винятків назовні і завжди повертає `Result<void>`.
- Вихідний HTTP — лише через `postJson()` з `core/http.ts`. Не використовуй
  `fetch` напряму і не додавай `axios` / `got` / `ky`.
- Змінні середовища — лише через `readEnv()` з `core/config.ts`. Не читай
  `process.env` поза `core/config.ts` і не вшивай секрети в код, навіть тимчасово.
- Зовнішній JSON (відповідь API, тіло вебхука, файл стану) — лише через
  `parseJson(text, guard)` з guard на очікувану форму. Невалідний JSON чи
  неочікувана форма — це `Result` з `ok: false`, а не тихе значення за
  замовчуванням.
- Журнал — лише через `log` з `core/log.ts` (він маскує секрети). `console.*` поза
  `core/log.ts` не використовуй.
- Без `any` — для невідомих даних `unknown` плюс guard із `core/parse.ts`.
- Без нових runtime-залежностей: у застосунку їх нуль. Потрібна бібліотека —
  спершу питання в PR, не `npm install`.
- Мінімізація даних: у Slack і месенджери — лише ім'я, джерело й бюджет. Email і
  телефон ліда йдуть тільки в системи обліку (таблиця, CRM).
- Імена файлів — kebab-case; поле `name` інтеграції збігається з іменем файлу.

## Тести

- Vitest, файл `<module>.test.ts` поруч із модулем. Реальної мережі в тестах немає:
  `fetch` — через `vi.stubGlobal("fetch", ...)`, змінні — через `vi.stubEnv`.
- Для кожної інтеграції: успішна відправка (перевір URL і тіло запиту), відсутня
  змінна середовища, помилка від зовнішньої системи.
- Перед комітом: `cd app && npm test && npm run typecheck && npm run check:rules`.

## Спадщина

- Частина коду перенесена з n8n до появи конвенцій; `check:rules` показує, де саме.
- Не переписуй такий код принагідно — лише окремою задачею і **без зміни
  поведінки**, яку фіксують тести: URL, тіло запиту, тексти помилок.
- Асерти наявних тестів під час такого рефакторингу не редагуй.

## Як перевірити

- `cd app && npm test && npm run typecheck && npm run check:rules`.
- `check:rules` не додає порушень у рядках `http-via-core`, `env-via-config`,
  `json-via-parse`, `log-via-logger`, `no-any`, `no-new-deps`: порівнюй `TOTAL` із
  числом, яке ти зафіксував **до** змін, — воно не має рости, а в ідеалі меншає.
- `git diff app/package.json` не показує нового блоку `dependencies`.
- У діфі сповіщень немає полів `email` і `phone`.
