# Конвенції коду

## Контекст

Ядро вже дає таймаут і повтори HTTP, перевірку форми даних і маскування секретів у
журналі. Код поза ядром користується ними, а не обходить їх
(`materials/architecture-brief.md`, розділи «Конвенції коду», «Тести», «Спадщина»).

## Правило

- **Помилки — значення.** Усе, що може не вдатися, повертає `Result<T>` з `core/types.ts`.
  `Integration.send()` завжди повертає `Promise<Result<void>>` і не кидає винятків: не
  `throw`, а `return { ok: false, error: "…" }`; помилковий `Result` від `postJson` /
  `readEnv` / `parseJson` повертай далі.
- **HTTP** — лише `postJson(url, body, options?)` з `core/http.ts`. Не `fetch`, не
  `axios` / `got` / `ky`, не `node:http(s)`.
- **Змінні середовища** — лише `readEnv(name)` з `core/config.ts`, імена — у `requiredEnv`.
  Не `process.env`. Секрети не логуй і не вшивай у код, навіть «тимчасово».
- **Зовнішній JSON** (відповідь API, вебхук, файл стану) — лише
  `parseJson(text, guard, label)` з `core/parse.ts` з guard на очікувану форму. Не
  `JSON.parse`. Невалідний JSON чи неочікувана форма → `{ ok: false, … }`, видимий у
  журналі; не підставляй тихо значення за замовчуванням.
- **Журнал** — лише `log.info` / `log.warn` / `log.error` з `core/log.ts` (маскує токени).
  Не `console.*`.
- **Без `any`** (`: any`, `as any`, `<any>`) — `unknown` + guard.
- **Без нових залежностей.** Не додавай пакети (`npm install <пакет>`, `npm i -D <пакет>`)
  і не змінюй `dependencies` у `package.json`; `npm install` без аргументів — можна.
  Імпорти в коді — лише `node:*` і відносні (у тестах ще `vitest`). Потрібна бібліотека —
  зупинись і спитай.
- **Мінімізація даних.** У сповіщення (Slack, месенджери) — лише ім'я, джерело й бюджет
  ліда; ніколи `email` і `phone`. Повні дані — лише в системи обліку (таблиця, CRM).
- **Імена.** Файли — kebab-case; `name` інтеграції = ім'я файлу без `.ts`.
- **Тести.** Vitest, `<module>.test.ts` поруч із модулем, без реальної мережі:
  `vi.stubGlobal("fetch", …)`, `vi.stubEnv(…)`, секрети — з префіксом `fake`. Для
  інтеграції мінімум: успіх (перевір URL і тіло запиту), відсутня змінна середовища,
  помилка від зовнішньої системи.
- **Спадковий код** (порушення з `check:rules`) — не зразок і не переписується попутно:
  це окрема задача без зміни поведінки. Зразок інтеграції — `integrations/slack-notify.ts`.

## Як перевірити

- `cd app && npm run check:rules` → жодне порушення не вказує на рядок, який ти додав
  чи змінив; TOTAL не більший, ніж до зміни.
- `cd app && npm test && npm run typecheck` → тести зелені, помилок типів немає.
- `grep -rnw --include="*.ts" --exclude="*.test.ts" "throw" app/src/integrations app/src/sync`
  → порожньо.
- Сповіщення: у тесті модуля фікстура має і `email`, і `phone`, а асерти перевіряють,
  що в тексті немає жодного з них (`not.toContain(lead.email)`, `not.toContain(...)` для телефону).
