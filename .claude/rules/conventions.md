# Конвенції коду lead-sync

## Контекст

Кожна конвенція нижче закриває конкретну аварію з n8n-часів: мовчазний `fetch`
без таймауту, токен у `console.log`, «значення за замовчуванням» замість
помилки. `npm run check:rules` перевіряє їх статично
(`materials/architecture-brief.md`, розділ «Конвенції коду»).

## Правило

1. **Помилки — це значення.** Функція, що може не вдатися, повертає `Result<T>`
   з `core/types.ts`. Не кидай `throw` назовні модуля; `send()` інтеграції
   **завжди** повертає `Result<void>`. Помилку прокидай далі як значення:
   `if (!result.ok) return result;`.
2. **HTTP — лише `postJson()`** з `core/http.ts` (там таймаут, повтори на 5xx/429,
   маскування URL). Не викликай `fetch` напряму і не додавай `axios` / `got` / `ky`.
   Потрібен метод, якого немає в `postJson` — зупинись і спитай.
3. **Змінні середовища — лише `readEnv(name)`** з `core/config.ts`.
   Не читай `process.env` поза `core/config.ts`. Імена обов'язкових змінних
   перелічуй у полі `requiredEnv` інтеграції. Значення секретів не логуй і не
   вшивай у код навіть «тимчасово».
4. **Зовнішні дані — лише `parseJson(text, guard)`** з `core/parse.ts`.
   Не викликай `JSON.parse` напряму. Guard будуй на `isRecord` / `isString` /
   `isNumber`. Невалідний JSON чи несподівана форма — це `Result` з `ok: false`,
   а не тихе значення за замовчуванням: пошкоджені дані мають бути видимі.
5. **Журнал — лише `log`** (`log.info` / `log.warn` / `log.error`) з `core/log.ts`:
   він маскує токени через `redact()`. Не використовуй `console.*` поза `core/log.ts`.
6. **Без `any`.** Для невідомих даних — `unknown` плюс guard. Ні `: any`,
   ні `as any`, ні `<any>`.
7. **Без нових залежностей.** У застосунку нуль runtime-залежностей. Не запускай
   `npm install <пакет>` і не додавай імпорт з пакета — тільки відносні шляхи
   й `node:*`. Потрібна бібліотека — питання в PR, а не встановлення.
8. **Мінімізація даних.** У сповіщення (Slack, месенджери) не передавай `lead.email`
   і `lead.phone` — лише `name`, `source` і `budgetUsd`. Повні дані йдуть тільки
   в системи обліку: таблиця, CRM.
9. **Імена.** Файли — kebab-case; поле `name` інтеграції збігається з іменем файлу.

### Тести

- Vitest, `<module>.test.ts` поруч із модулем. Реальної мережі немає:
  `vi.stubGlobal("fetch", ...)`, змінні — `vi.stubEnv`.
- Для кожної інтеграції — три випадки: успішна відправка (перевір URL і тіло
  запиту), відсутня змінна середовища, помилка від зовнішньої системи.
- Рефакторинг спадкового коду — **без зміни поведінки**, яку фіксують тести
  (URL, тіло запиту, тексти помилок). Не редагуй асерти, щоб тест позеленів.

## Як перевірити

- `cd app && npm run check:rules` — у блоці `by rule` рядки `http-via-core`,
  `env-via-config`, `json-via-parse`, `log-via-logger`, `no-any`, `no-new-deps`
  **не зросли** проти поточного стану (`TOTAL: 1` — лишилось `json-via-parse`
  у `app/src/sync/state.ts`, спадок, який переписують окремою задачею).
- `cd app && npm test` — зелений; `cd app && npm run typecheck` — без помилок.
- `git diff package.json` — блок `dependencies` не з'явився.
- Сповіщення: `grep -n "email\|phone" app/src/integrations/slack-notify.ts` — порожньо.
