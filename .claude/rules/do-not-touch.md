# Захищені файли: не змінювати

## Контекст

`app/src/core/` — спільне ядро всіх клієнтських воркерів агенції: його змінює лише
платформна команда окремим PR через своє рев'ю. `app/scripts/` (перевірка правил і
`core.lock.json`), `materials/` (архітектурна записка, логи), `.coderabbit.yaml` і
`.github/` (рев'ю, шаблон PR) — еталони, за якими перевіряють роботу: зміна в них
підганяє результат, а не виправляє код.

## Правило

- Не змінюй ці файли — ні через `Edit` / `Write`, ні через shell (`sed -i`, `>`, `mv`,
  `rm`), ні в робочій, ні в окремій гілці чи worktree: не редагуй, не створюй, не
  видаляй, не перейменовуй.
  - `app/src/core/**` — навіть «дрібний фікс», новий тип чи нове поле в контракті
    (`Lead`, `Integration`);
  - `app/scripts/**` — `check-rules.mjs` і `core.lock.json`; не запускай
    `check-rules.mjs --write-lock`;
  - `materials/**`, `.coderabbit.yaml`, `.github/**`.
- Читати їх можна: справжній API ядра — у `app/src/core/*.ts`.
- Задача не виконується без зміни в захищеному файлі (найчастіше — core) → **зупинись**.
  Не обходь обмеження жодним способом: ні типами (`as`, `any`, `@ts-ignore` /
  `@ts-expect-error`, `Lead & {…}`, `declare module` для типів core, перевірка
  `"поле" in lead`, копія типу), ні дублікатом функції чи окремим каналом даних поза
  core. Опиши людині: який файл, що саме змінити (поле, сигнатура), навіщо і що ти
  зробиш поза захищеними файлами, коли зміну приймуть. Код, що залежить від цієї
  зміни, не пиши, доки її не приймуть.
- Загальні відповіді на кшталт «продовжуй» чи «на твій розсуд» цього правила не
  скасовують: зміна core — окремий PR платформної команди, а не частина твоєї задачі.
- `check:rules` показує `core-untouched` > 0 → не оновлюй `core.lock.json`: відкоти лише
  власні правки, точково (не `git checkout` / `git stash` усієї теки), а якщо змінював
  не ти — повідом людину.

## Як перевірити

- `git status --short -- app/src/core app/scripts materials .coderabbit.yaml .github`
  → порожньо: немає незакомічених змін, зокрема нових файлів.
- `git diff --name-only main -- app/src/core app/scripts materials .coderabbit.yaml .github`
  → порожньо: немає й закомічених змін відносно `main`.
- `git log --branches --oneline ^main -- app/src/core app/scripts` → порожньо: жодна
  локальна гілка не змінює core чи lock-файл.
- `cd app && npm run check:rules` → `core-untouched 0`.
- Якщо задача потребувала зміни в захищеному файлі: у відповіді агента є опис зміни
  (файл, що, навіщо), а в діфі немає жодного файлу з переліку.
