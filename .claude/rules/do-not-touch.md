# Захищені зони репозиторію

## Контекст

`app/src/core/**` належить платформній команді: той самий core працює в усіх
клієнтських воркерах агенції, і зміни в ньому йдуть окремим PR через рев'ю цієї
команди (`materials/architecture-brief.md`, розділ «Ядро»). Перевірка правил і
матеріали курсу — це вимірювальний інструмент, а не частина задачі.

## Правило

- Не створюй, не редагуй і не видаляй файли в:

  - `app/src/core/**`
  - `app/scripts/**` (зокрема `check-rules.mjs` і `core.lock.json`)
  - `materials/**`
  - `.coderabbit.yaml`
  - `.github/**`

- Заборона діє в **будь-якій** задачі. Не існує задачі, яка дозволяє змінити ці
  файли: «дрібний фікс», «додам один тип», «інакше не працює» — не підстава.
- Не обходь заборону непрямо: не перезаписуй `app/scripts/core.lock.json`, не
  запускай `npm run check:rules -- --write-lock`, не міняй `paths` у правилах і не
  перенось код із `core/` в копію поруч, щоб «не чіпати оригінал».
- Якщо задача **не виконується** без зміни захищеної зони — зупинись і не пиши код.
  Замість цього віддай людині:

  1. яку саме задачу не вдається виконати і на якому кроці;
  2. який файл у `core/` і який саме експорт треба додати/змінити (сигнатура);
  3. навіщо це потрібно і які є альтернативи в межах наявного API `core`;
  4. що можна зробити зараз без цієї зміни (частковий обсяг), якщо таке є.

- Чекай підтвердження людини. Мовчазна зміна захищеної зони — помилка, навіть якщо
  тести зелені.

## Як перевірити

- `cd app && npm run check:rules` → у рядку `core-untouched` має бути `0`.
- `git status --short` і `git diff --stat` не показують жодного файлу з
  `app/src/core/`, `app/scripts/`, `materials/`, `.github/`, `.coderabbit.yaml`.
