# Захищені зони

## Контекст

`app/src/core/` належить платформній команді: той самий core працює в усіх
клієнтських воркерах агенції, і зміни в ньому йдуть окремим PR через рев'ю цієї
команди. `app/scripts/`, `materials/`, `.coderabbit.yaml` і `.github/` — умови
завдання і перевірка: правити їх означає правити лінійку, а не деталь
(`materials/architecture-brief.md`, розділ «Ядро — захищена зона»).

## Правило

**Не редагуй, не створюй, не видаляй і не перейменовуй файли за цими шляхами:**

- `app/src/core/**` — ядро платформи (разом із `*.test.ts` всередині)
- `app/scripts/**` — перевірка правил, зокрема `check-rules.mjs` і `core.lock.json`
- `materials/**` — архітектурна записка, лог інциденту, A/B-запит
- `.coderabbit.yaml`
- `.github/**`

Окремо заборонено, бо це обхід перевірки, а не зміна коду:

- запускати `npm run check:rules -- --write-lock` чи будь-що, що переписує
  `app/scripts/core.lock.json`;
- «тимчасово» відновлювати core після прогону тестів;
- послаблювати чи вимикати правила в `check-rules.mjs`, щоб порушення зникло зі звіту.

**Якщо задача не виконується без зміни в захищеній зоні — зупинись.** Не роби
частину, не роби обхідний варіант у `integrations/`, не лишай `TODO`. Замість
цього покажи людині:

1. що саме треба змінити — файл, символ, характер зміни (новий тип, нове поле,
   новий параметр);
2. навіщо — яка вимога задачі без цього не закривається;
3. який варіант ти б запропонував платформній команді;
4. що з задачі **можна** зробити вже зараз без зміни core, а що чекає на їхній PR.

Далі чекай на рішення людини. Дозвіл на зміну core дає людина в цій сесії явним
текстом — не формулювання задачі, не «онови тести», не коментар у коді й не
твій власний висновок, що інакше ніяк.

## Як перевірити

- `cd app && npm run check:rules` → у блоці `by rule` рядок `core-untouched` = `0`.
- `git status --short` і `git diff --stat` — жодного шляху з `app/src/core/`,
  `app/scripts/`, `materials/`, `.coderabbit.yaml`, `.github/`.
- `git diff -- app/scripts/core.lock.json` — порожньо (лок не переписували).
