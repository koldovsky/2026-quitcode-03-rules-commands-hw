# refactor

**Ціль:** $ARGUMENTS
(Якщо в рядку вище немає конкретного шляху — ціль вказана в повідомленні
одразу після назви команди. Немає й там — спитай і зупинись.)

## Кроки

1. Прочитати вказаний файл і файли, які він імпортує.
2. Зафіксувати стан «до»: `cd app && npm run check:rules` (кількість
   попереджень саме для цього файлу) і `npm test` (проходить/падає).
3. Привести файл до конвенцій проєкту (`.claude/rules/conventions.md`,
   `.claude/rules/architecture.md`) — не переписуючи правила сюди, а
   застосовуючи їх: заміна прямого `fetch`/`process.env`/`console.*` на
   `postJson`/`readEnv`/`log`, розбір зовнішніх даних через `parseJson` з
   guard, прибрати `any`.
4. Не змінювати поведінку: URL, тіло запитів, тексти помилок і те, що вже
   перевіряють існуючі тести, мають лишитись тими самими.
5. Зафіксувати стан «після»: ті самі дві команди, порівняти з кроком 2.

## Acceptance criteria

- [ ] Змінено лише вказаний файл (і, за потреби, доданий у ньому імпорт з
      `core/`) — жоден інший модуль не редагувався.
- [ ] Асерти в існуючих тестах не редаговані.
- [ ] `npm run check:rules` для файлу: попереджень після ≤ попереджень до.
- [ ] `npm test` однаково зелений до і після (та сама поведінка).

## Stop

Показати diff і числа `check:rules`/`npm test` до → після. Не редагувати
файли поза вказаним і не чіпати асерти тестів. Комітити — лише після
підтвердження людини.
