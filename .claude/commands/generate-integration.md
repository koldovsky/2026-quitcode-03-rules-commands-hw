# Generate integration

**Ціль:** $ARGUMENTS
(Якщо в рядку вище немає назви сервісу — ціль вказана в повідомленні одразу
після назви команди. Немає й там — спитай і зупинись.)

## Кроки

1. **Прочитай зразок**: `app/src/integrations/slack-notify.ts` і
   `slack-notify.test.ts`, контракт `Integration` у `app/src/core/types.ts`,
   реєстр `app/src/integrations/index.ts`. Нову форму не вигадуй — повтори наявну.
2. **Визнач параметри інтеграції** і покажи їх людині одним списком перед тим,
   як писати код:
   - `name` у kebab-case = ім'я файлу (напр. `hubspot-contact`);
   - `requiredEnv` — імена змінних середовища, **лише імена**;
   - URL і форма тіла запиту;
   - які поля ліда йдуть у запит. Якщо це сповіщення (Slack, месенджер) —
     `email` і `phone` не йдуть, діє правило мінімізації даних.
   Якщо щось із цього невідоме — обери розумний дефолт і **познач його явно** як
   припущення, а не як факт.
3. **Створи `app/src/integrations/<name>.ts`**: об'єкт типу `Integration`,
   `send(lead): Promise<Result<void>>`, HTTP через `postJson()`, змінні через
   `readEnv()`, журнал через `log`, помилки як `Result`. Деталі — у правилі
   `conventions`, сюди їх не переписуй.
4. **Створи `app/src/integrations/<name>.test.ts`** — три випадки з правила
   `conventions`: успішна відправка (перевір URL і тіло запиту), відсутня
   змінна середовища, помилка від зовнішньої системи. Мережу підміняй
   `vi.stubGlobal("fetch", ...)`, змінні — `vi.stubEnv`.
5. **Додай рівно один рядок** у `app/src/integrations/index.ts`: імпорт і елемент
   масиву `integrations`.
6. **Перевір**:
   ```bash
   cd app && npm test
   cd app && npm run check:rules
   cd app && npm run typecheck
   ```
7. **Покажи підсумок**: створені файли, `name`, `requiredEnv`, числа з перевірок
   і окремим списком — усі припущення з кроку 2, які людині треба підтвердити.

## Acceptance criteria

- [ ] Рівно два нових файли + один змінений (`index.ts`): `git status --short`.
- [ ] `npm test` зелений; нових тестів — **щонайменше три** (успіх, відсутня
      змінна середовища, помилка зовнішньої системи); більше — можна, якщо
      модуль має ще одну гілку логіки.
- [ ] `npm run check:rules` не показує нових порушень; `TOTAL` не зріс проти базової лінії.
- [ ] `tsc --noEmit` без помилок; у новому коді немає `any`.
- [ ] `name` збігається з іменем файлу; `requiredEnv` містить лише імена змінних,
      жодного значення секрету в коді чи тестах.
- [ ] `git status --short` не показує жодного шляху із захищених зон.
- [ ] `git diff -- app/package.json` порожній — нових залежностей немає.

## Stop

Не чіпай `app/src/core/**` — навіть якщо для сервісу бракує типу чи параметра в
`postJson()`. У такому разі зупинись і опиши потребу за процедурою з правила
`do-not-touch`.

Не додавай SDK сервісу чи HTTP-клієнт — тільки `postJson()`. Якщо сервіс
принципово не працює через `postJson()` (потрібен не-JSON body, OAuth-флоу,
websocket) — зупинись, поясни й запропонуй варіанти, коду не пиши.

Наприкінці покажи підсумок і список припущень — і чекай на підтвердження,
перш ніж щось комітити.
