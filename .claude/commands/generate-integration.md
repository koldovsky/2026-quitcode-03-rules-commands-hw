# generate-integration

**Ціль:** $ARGUMENTS
(Якщо в рядку вище немає конкретної назви сервісу — ціль вказана в
повідомленні одразу після назви команди. Немає й там — спитай і зупинись.)

## Кроки

1. Прочитати одну наявну інтеграцію (напр.
   `app/src/integrations/slack-notify.ts`) і її тест поруч — як приклад
   стилю та структури `send()`.
2. Прочитати контракт `Integration` і тип `Lead` у `core/types.ts`, щоб
   реалізація відповідала контракту.
3. Створити `app/src/integrations/<kebab-name>.ts` за контрактом, дотримуючись
   `.claude/rules/architecture.md` (публічний API ядра) і
   `.claude/rules/conventions.md` (Result, `postJson`/`readEnv`/`log`, без
   `any`, без email/телефону в тілі запиту, якщо це сповіщення).
4. Створити `app/src/integrations/<kebab-name>.test.ts` поруч, за патерном
   існуючих тестів: успішна відправка (перевірити URL і тіло запиту),
   відсутня змінна середовища, помилка від зовнішньої системи.
5. Додати один рядок реєстрації нової інтеграції в
   `app/src/integrations/index.ts`.
6. Прогнати `cd app && npm test` і `npm run check:rules`.

## Acceptance criteria

- [ ] Створено рівно два нових файли (модуль і тест) плюс одна зміна —
      рядок реєстрації в `index.ts`. `app/src/core/**` не змінено.
- [ ] Нових залежностей не додано (`package.json` без змін у dependencies).
- [ ] `npm test` зелений; `npm run check:rules` без нових порушень.

## Stop

Показати підсумок: які файли створено, рядок реєстрації, результат тестів
і `check:rules`. Core не чіпати, нових залежностей не додавати. Коміт —
лише після підтвердження людини.
