# refactor

**Ціль:** $ARGUMENTS
(Якщо в рядку вище немає конкретного файлу — ціль вказана в повідомленні одразу
після назви команди. Немає й там — спитай і зупинись.)

## Кроки

1. Зафіксуй стан **до**: `cd app && npm test` і `npm run check:rules`. Випиши число
   порушень саме для цільового файлу і рядки правил, у яких вони є.
2. Прочитай цільовий файл, його тест і сусідній модуль, що вже відповідає
   конвенціям (напр. `app/src/integrations/slack-notify.ts`) — як зразок стилю.
3. Перепиши файл за `.claude/rules/conventions.md` і `.claude/rules/architecture.md`.
   Поведінка, яку фіксують тести, лишається незмінною: URL, тіло запиту, тексти
   помилок, значення, що повертаються.
4. Зафіксуй стан **після**: ті самі дві команди плюс `npm run typecheck`.
5. Покажи таблицю до → після: порушення для файлу, `TOTAL`, кількість тестів.

## Acceptance criteria

- [ ] Змінено лише вказаний файл; його тест не редаговано взагалі.
- [ ] `cd app && npm test` зелений; кількість тестів не змінилася.
- [ ] `npm run check:rules` для цільового файлу зменшився; `TOTAL` не виріс.
- [ ] `npm run typecheck` без помилок.
- [ ] URL, тіло запиту і тексти помилок збігаються з тими, що були до рефакторингу.

## Stop

Не чіпай нічого поза цільовим файлом і його імпортами. **Асерти в тестах не
редагуй** — якщо тест падає, причина в рефакторингу, а не в тесті: зупинись і
покажи розбіжність людині. Якщо для конвенційності бракує API в `core/` —
діє `.claude/rules/do-not-touch.md`: зупинись і опиши потребу.
