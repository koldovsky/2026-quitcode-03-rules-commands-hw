# Refactor to conventions

**Ціль:** $ARGUMENTS
(Якщо в рядку вище немає конкретного файлу — ціль вказана в повідомленні одразу
після назви команди. Немає й там — спитай і зупинись.)

## Кроки

1. **Зафіксуй базову лінію ДО** — це вхідні дані, без них рефакторинг не можна
   перевірити:
   ```bash
   cd app && npm test
   cd app && npm run check:rules
   ```
   Випиши: скільки тестів зелених, `TOTAL: N`, і скільки порушень саме у цього
   файлу в блоці `by file` — з іменами правил із блоку списку.
2. **Прочитай ціль і її тест** (`<файл>.test.ts`), а також сусідній модуль, який
   уже відповідає конвенціям, — як зразок форми. Для інтеграцій це
   `app/src/integrations/slack-notify.ts`.
3. **Випиши перелік замін** перед тим, як правити: кожне порушення зі звіту →
   конкретна заміна з правила `conventions` (`fetch` → `postJson`,
   `process.env` → `readEnv`, `JSON.parse` → `parseJson` + guard,
   `console.*` → `log`, `any` → `unknown` + guard). Правила не переписуй сюди —
   вони вже в контексті.
4. **Заміни по одній.** Після кожної — `npm test`.
   Поведінка, яку фіксують тести, не змінюється: той самий URL, те саме тіло
   запиту, ті самі тексти помилок, той самий публічний експорт файлу.
5. **Зафіксуй лінію ПІСЛЯ** тими самими двома командами і порівняй з кроком 1.
6. **Покажи таблицю до/після**: тести, `TOTAL`, порушення цього файлу за іменами
   правил, і що саме змінилося в коді.

## Acceptance criteria

- [ ] `npm test` зелений і кількість тестів **та сама**, що до рефакторингу.
- [ ] Порушень цього файлу в `check:rules` стало **менше**; `TOTAL` не зріс.
- [ ] Асерти в тестах не редаговані: `git diff -- '*.test.ts'` порожній.
- [ ] Публічний експорт файлу не змінився — імпорти в інших модулях не правилися.
- [ ] Змінено рівно один файл (`git status --short`), крім випадку, коли зміна
      імпорту в `integrations/index.ts` неминуча — тоді скажи про це явно.
- [ ] Жодного шляху із захищених зон у `git status --short`.

## Stop

Редагуй **лише вказаний файл**. Не «заодно» інші порушення зі звіту — для них
окремий виклик команди.

Зупинись і спитай, якщо:
- прибрати порушення неможливо без зміни `app/src/core/**` — опиши потребу за
  процедурою з `do-not-touch`;
- тест падає після заміни, і щоб його полагодити, треба змінити асерт — це означає,
  що змінилась поведінка: відкоти заміну й покажи, в чому конфлікт;
- порушення зникає лише через нову залежність.
