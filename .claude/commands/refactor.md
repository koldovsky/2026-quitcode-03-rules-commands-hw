# Refactor

**Ціль:** $ARGUMENTS
(Якщо в рядку вище немає конкретного файлу — ціль вказана в повідомленні одразу
після назви команди. Немає й там — спитай і зупинись.)

## Кроки

1. **Зафіксуй «до»** і збережи вивід дослівно — він потрібен у підсумку:
   ```bash
   cd app && npm test && npm run check:rules
   ```
   Випиши окремо порушення саме цього файлу з розділу `by file`.
2. Прочитай сам файл, його тест і кожен модуль, що його імпортує
   (`grep -rn "<ім'я-файлу>" app/src`). Тест — це специфікація поточної поведінки.
3. Перепиши файл під `.claude/rules/conventions.md` і `architecture.md`.
   Правила не переписуй у відповідь — посилайся на них.
4. **Поведінка не змінюється.** Незмінними лишаються: URL і його складання, тіло
   запиту, заголовки, тексти помилок, формат рядків журналу, сигнатура експорту
   для зовнішніх викликачів. Змінюєш форму, а не те, що видно ззовні.
5. Змінився вид експорту (напр. `export default` → іменований) — онови **всі**
   місця імпорту, включно з `integrations/index.ts`, і скажи про це в підсумку окремо.
6. **Зафіксуй «після»** тими самими командами.

## Acceptance criteria

- [ ] `npm test` зелений, і кількість тестів **та сама**, що до рефакторингу.
- [ ] Асерти в тестах не редаговані: `git diff -- '*.test.ts'` не містить змін
      у рядках `expect(...)`.
- [ ] `check:rules` для цього файлу → `0`; TOTAL зменшився рівно на стільки,
      скільки порушень було в цьому файлі.
- [ ] `npm run typecheck` зелений.
- [ ] Змінено лише цільовий файл і місця його імпорту — нічого більше:
      `git status --short` це підтверджує.
- [ ] Жодного нового пакета, жодної зміни в захищених шляхах.

## Stop

Зупинись і спитай, якщо: (а) щоб прибрати порушення, треба змінити те, що
перевіряє тест; (б) потрібна функція, якої немає в публічному API ядра;
(в) файл лежить у захищеній зоні. Не «підправляй» тест під новий код —
тест тут головніший за код.

У підсумку покажи таблицю: `check:rules` до/після (усього і по цьому файлу),
`npm test` до/після, список змінених файлів.
