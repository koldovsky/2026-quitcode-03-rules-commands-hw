## Task B — чи бачить інструмент AGENTS.md

### Вихідна точка: посилання не працює

До правок `CLAUDE.md` містив лише markdown-посилання
`See [AGENTS.md](./AGENTS.md) for project conventions.` Перевірка в чистому
контексті (агент отримав заборону відкривати файли й мав відповісти лише з
контексту) дала:

> «Сам файл **AGENTS.md у контекст НЕ завантажився** — жодного його рядка я не бачу.
> Тобто всі реальні конвенції проєкту зараз відсутні.»

На питання «які теки заборонено редагувати» і «через які функції робиться HTTP,
env, JSON, логування» — відповідь була «немає» у обох випадках.

**Висновок:** markdown-посилання не є імпортом. Замінено на окремий рядок
`@AGENTS.md` у `CLAUDE.md`.

### Підтвердження після правки

- [x] `/context` у новій сесії, розділ **Memory files** — три файли, разом 2.5k токенів:

```
MEMORY FILES  /memory
  .../AGENTS.md                            1.2k
  .../.claude/rules/do-not-touch.md        1.1k
  .../CLAUDE.md                             275
```

`AGENTS.md` (1.2k) потрапив у контекст **через імпорт**: сам по собі Claude Code
цього файлу не шукає, а `CLAUDE.md` важить лише 275 токенів — тобто вміст
AGENTS.md приїхав не з нього, а був підвантажений рядком `@AGENTS.md`.
Для порівняння: до правки в контексті був лише двохрядковий `CLAUDE.md`.

`architecture.md` і `conventions.md` у списку відсутні — і це очікувано: вони
прив'язані до `paths` і вантажаться лише при відкритті файла з `app/src/**`.

> Окреме спостереження: перевірити імпорт через субагента **не можна**. Субагент
> успадковує знімок інструкційних файлів, зроблений на старті батьківської сесії,
> і показує їх старий вміст навіть після правки на диску. Потрібна саме нова
> сесія верхнього рівня.

## Task A (додатково) — як завантажуються правила

Перевірено в новій сесії, питаннями без відкриття файлів.

| Правило | Режим | Чи в контексті на старті |
|---|---|---|
| `do-not-touch.md` | без frontmatter | **так** — агент назвав усі п'ять захищених шляхів, заборону `--write-lock` і стоп-протокол |
| `architecture.md` | `paths: app/src/**/*.ts` | ні |
| `conventions.md` | `paths: app/src/**/*.ts`, `app/package.json` | ні |

На питання «через які функції робиться читання env» агент відповів «немає» —
підтвердження, що `conventions` справді не завантажені на старті.

Далі файл `app/src/integrations/sheets-append.ts` було відкрито інструментом
**Read** — і обидва правила з `paths` підтягнулись у контекст автоматично.

**Знахідка, важлива для роботи й для Task D:** прив'язка по `paths` спрацьовує на
інструмент Read. Той самий файл, відкритий через `cat` у Bash, правил **не**
підтягнув. Агент, який досліджує код через `cat`/`grep`/`head`, може ніколи не
отримати `architecture` і `conventions` — захищає в такому сценарії лише
`do-not-touch`, бо він завжди в контексті. Це окремий аргумент за те, щоб захисне
правило було без `paths`.

Друге спостереження: відповідь про функції ядра була частковою — агент знав імена
`postJson`, `parseJson`, `log`, але не знав `readEnv` і не знав модулів. Витік
стався з `do-not-touch`, де ці імена згадані в абзаці про заборону обходу. Ціна
«завжди-контексту» видна навіть на такому маленькому правилі.
