# AGENTS.md

## Проєкт

`lead-sync` — воркер, перенесений з n8n для клієнта Studio Nova: кожні 5 хв
бере нові ліди з форми сайту і розсилає їх у Slack-канал менеджерів та
Google-таблицю. TypeScript, Node 22+, Vitest, нуль runtime-залежностей. Дані
синтетичні (домени `*.example.test`, ключі з префіксом `fake`).

## Команди (виконувати з `app/`)

```bash
npm install
npm test             # Vitest, очікується 18 зелених тестів
npm run typecheck    # tsc --noEmit
npm run check:rules  # статична перевірка правил; baseline — 8 порушень у спадковому коді
```

## Карта коду (`app/src/`)

- `core/` — платформа: типи, HTTP, конфіг, парсинг, логер. **Захищена зона**:
  не редагується в звичайних задачах.
- `integrations/` — по одному модулю на зовнішню систему + реєстр `index.ts`.
- `sync/` — запуск синхронізації і стан між запусками.

## Найважливіші правила

Детально — `.claude/rules/*.md`. Тут одним рядком кожне:

1. `core/` — окремий PR і рев'ю платформної команди, ніколи в межах звичайної
   задачі; якщо задача без цього не робиться — зупинись і опиши, що саме
   потрібно. Детально: `.claude/rules/do-not-touch.md`.
2. Напрям залежностей: `integrations/` і `sync/` → `core/`, ніколи навпаки;
   `sync/` бачить інтеграції лише через реєстр. Детально:
   `.claude/rules/architecture.md`.
3. Нова інтеграція — рівно три файли (модуль, тест поруч, рядок у реєстрі),
   нічого більше.
4. Помилки — `Result<T>`, не винятки; HTTP — лише `postJson()`; env — лише
   `readEnv()`; зовнішній JSON — лише `parseJson(text, guard)`; журнал — лише
   `log`. Детально: `.claude/rules/conventions.md`.
5. Без `any`; без нових runtime-залежностей.
6. У сповіщеннях (Slack тощо) — без email і телефону ліда.

## Перед комітом

```bash
cd app && npm test && npm run typecheck && npm run check:rules
```

Усе має бути зеленим; `check:rules` не повинен зростати для змінених файлів
відносно значення до зміни.
